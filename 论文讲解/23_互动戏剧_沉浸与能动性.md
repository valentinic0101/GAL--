## 二、论文本身

### 2.1 要解决的问题

LLM 互动戏剧的核心矛盾：**沉浸感**（剧情好看、有戏剧结构）与**能动性**（玩家说什么都被接住、影响走向）难以兼得。纯角色 agent 自由对演剧情平庸，纯剧本驱动玩家没有自由。

### 2.2 方法：双层架构 + 两项技术

1. **Playwriting-guided Generation（编剧/导演层）**：
   - 从 **8 种现代戏剧情境**（Love、Phoenix、Cinderella、Love Triangle、Revenge、Family、Reunion、Savior——源自 Polti 36 戏剧情境）× **6 种叙事技巧**（Suspense、Twist、Non-linear、Multiple narrative、Irony、Symbolism）中采样组合；
   - GPT-4o 生成故事 → critic LLM 点评 → 修改，**3 个独立 LLM 投票**迭代；
   - 最后转成 **3–5 场的剧本**（每场含角色设定 + 情节序列）。
2. **角色层：plot-based reflection**：角色 agent 沿 plot chain 行动，**每 5 步**检查玩家言行并做**有界更新**（最多改 1 个未完成 plot 或插入 1 个新 plot）——能动性被吸收进剧本，但每次只动一点，骨架不散。
3. **三种架构变体**：**Director-Actor**（导演 agent 只向演员下发"动机 z_t"，演员看不到剧本——防剧透）／**One-for-All**（单一全局 agent）／**Hybrid**（说明性场景用 One-for-All，互动场景切 Director-Actor）。
4. **出戏输入应对**：玩家跳出戏时用 Avoid / Ignore-Question / Associate（转移到相关剧情）等策略。

### 2.3 关键结果

- 故事质量显著优于 outline-first 基线（suspense 32% vs 10%、emotional tension 48% vs 10% 的 win-rate）；
- 反思机制把 agency 从 3.5 提到 4.0（1–5 分制）；Hybrid 架构加速 ×1.49；
- 代价：编剧层生成耗时 10–12 倍（离线预生成可接受）。

## 三、评价所用的技术

两部分人评，都值得抄：

1. **故事质量**：50 个人工前提段，6 名有戏剧知识的标注者，win-rate 对比基线，四维（conflict/suspense/emotional tension/character arc）+ 叙事技巧遵循率（92% vs 无 critic-revise 的 66%）；
2. **交互体验**：**10 名真人玩家（被分配人格设定）+ 10 个 GPT-4o 对抗玩家** × 3 场景共 **60 局**；1–5 分评 **7 维**：沉浸侧 4 维 + agency 侧 Player Influence / Intention Following / Speedup；
3. **消融**：reflection 开关 × 三种架构全交叉（director-actor 在角色魅力上占优，Hybrid 在叙事推进上 4.3 vs 3.6）；
4. **定性副作用**：reflection 会泄露剧本内容、生成不存在的场景——"反思层知道全部真相"本身就是泄漏源。

## 四、对 GAL 项目的启发

1. **Director-Actor 信息隔离 = 谜团锁的架构级解法**：演员 agent 看不到剧本只拿到动机——深雪不需要"被告知保密"，她根本**看不到**谜底，串戏/泄漏从架构上被消灭。这与架构 V1"知识边界防串戏"完全一致，且多了"导演→动机"的传递机制。
2. **plot-based reflection 每 5 步、最多改 1 个 plot**：本项目的 P0~P10 状态更新照此设计——玩家每次自由输入后，导演只在下一节拍做**有界修订**，防止剧本被玩家一波带跑或被 AI 悄悄换掉。
3. **7 维评测直接搬**：沉浸 4 维 + Player Influence + Intention Following + Speedup 就是"剧情引力是否有效"的验收表；真人玩家 + 对抗玩家（GPT-4o 故意出戏）混合测试的设计尤其适合谜团锁压力测试。
4. **Poli 情境 × 叙事技巧采样**：P1~P10 每个事件可以标注戏剧情境与主导技巧，导演层排程时保证技巧不连续重复（连续三个 Twist 会疲劳）。
5. **成本结构启示**：贵的是"编剧层离线生成"，便宜的是"运行时 reflection"——与本预算模型一致（每回合 3–5 次调用），剧本可以提前批量生成。
