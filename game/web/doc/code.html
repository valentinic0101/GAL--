1. 启动链路：从命令到可玩

python3 -m uvicorn server.app:app --port 8300 → 载入 app.py → import 链 → engine.Engine() 构造 → World()（不变量/空知识库/关系矩阵 50/50）+ Director(world) → 全局单例 engine → 挂载静态目录 /assets（资产）与 /（web/，html=True）→ 浏览器 GET / 返回 index.html → 标题页 → 点「开始游戏」→ POST /api/new → Engine.new_game() → 进入 P1。
  • 导入顺序：app.py → engine（包：core ← config / storage）→ world / director.director / director.gossip / agents.* / scenes.script。无循环依赖：world 不依赖任何上层；scenes 只被 engine 引用。
  • LLM = LLMAdapter() 在 import 时构造：读 game/llm.json（或环境变量），此时即确定可用性。
  • 全局单例意味着所有浏览器会话共享同一局游戏（见 §17 限制）。

4.2 类

Knowledge(key, content, source='witness', hops=0, distorted=False)

一条知识。source ∈ witness（亲眼）/ heard（听说）；hops 传播手数（≥3 不再传播）；distorted 是否走样。

Relation(a, b) → .affection/.trust (0~100) / .log / .change(da, dt, reason)

关系矩阵条目，全部变更带理由记录（变更日志进存档，可审计）。

WorldEvent(kind, data) → to_dict()

事件总线条目：player_say / player_move / scene_enter / scene_end / knowledge / relation / gossip / day_end / game_start。

World → emit / know / knows / knowledge_of / rel / change_relation / affection / to_dict / load
  • affection(a,b) = 矩阵值 + miyuki_affection_extra（主线的额外好感加成，钳制 0~100）。
  • to_dict()/load() 完整序列化——存档即状态快照，配合 events jsonl 实现事件溯源。

5. 运行时引擎 server/engine/ —— 方法全解

引擎原为单文件 engine.py，2026-09-17 按职责拆为包：core.py（Engine 类，推进与应答）、config.py（阶段提示与 BGM/转场/演员表）、storage.py（存档落盘）。下文的 Engine.xxx() 方法均在 core.py。

方法职责
sprite_of(char, expr)按阶段选立绘：修二 P7+ 用 teen、此前 child；深雪按表情映射 5 张 SVG；幻影 yukihime 用 white。
frame(kind,…)帧工厂：组装 §3 结构；计算在场人物（SCENE_CAST 或 Director.present_chars）；旁白/台词/玩家帧写入 history（backlog）。
new_game()重置 World+Director+history → enter_scene('P1')。
enter_scene(id)置 scene_id/beat_idx=0/mode='scene'/pending_choices=None（防卡死，01:45 夜间事故修复点）→ 返回 [标题卡帧, 首拍]。
step()状态机主循环：按 beat 类型消费脚本——narration/line/me 直接出帧；choice/free 挂起 pending_choices 等输入；effect 静默应用后 continue；脚本耗尽 → end_scene()。
apply_effect(beat)旗标合并 / 好感加成（extra+矩阵双写）/ 地点与时间切换 / daily_life_count 递增。
end_scene()见 §6 通路 A 尾部。
_witness(sid)事件→目击者知识库：P1 亲戚目击「黑长发女孩牵走修二」、P3 修二记住「她自称姐姐」、P7 记住「三年仍在等」等——这些正是八卦传播的种子。
interlude_act(action, payload)幕间三动作 + 叙事压力 +6；详见 §8 通路 C。
submit_input(text, choice_index)见 §7 通路 B。
_agentRespond(char, text)Agent 应答总入口：LLM 优先（重试≤2，护栏合格才收）→ 失败回落规则引擎；统一结算 effects（好感/旗标）。
advance()场景内步进；幕间返回氛围帧；pending_choices 挂起时原样返回（前端仍显示选项）。
enter_offered_scene()「▶ 推进剧情」按钮 → Director 仲裁 → enter_scene。
save(slot)/load(slot)JSON 快照 + world.events 追加写入 events_{slot}.jsonl 后清空（批次溯源）。

模块级映射表：STAGE_NOTES（P1/P2 禁止姐姐宣言、P3 才初告、P6 前不报名字——防 LLM 泄漏后设）、SCENE_BGM/LOC_BGM（音乐映射）、TRANSITIONS（P7 时 day 跳 1000 表示三年后）、SCENE_CAST（各场景在场人物，P0 只有 shuuji+yukihime）。

6. 运行通路 A：场景推进（点「下一步」）

前端点击对话框/回车 → advance()（web/js/50_flow.js，busy 防重入）→ POST /api/advance → Engine.advance() → pending_choices 为空 → step() 读 SCENES[scene_id].beats[beat_idx]：
· narration → narration 帧（斜体居中框）→ beat_idx+1 返回
· line → line 帧：who→CHAR_NAME 名牌、expr→立绘切换（normal/smile/sad/surprise/white）、action→斜体动作行
· me → 玩家台词帧（金色名牌「修二」）
· choice → 挂起 pending_choices，帧带 options；前端渲染选项按钮 +「自由输入」入口
· free → 同上但纯开放输入
· effect → apply_effect() 静默应用，continue 不出帧
拍耗尽 → end_scene()：_witness 写目击知识 → TRANSITIONS 推天数（P6→P7 时 day 1000=三年跳）→ mode='interlude' → 幕间帧 + _after_interlude()：Director.should_advance() 仲裁 → meta.scene_offer 高亮「▶ 推进剧情」。

7. 运行通路 B：玩家输入（选项/自由输入/交谈）

POST /api/input {text 或 choice_index} → submit_input()：
① 出「修二」帧（玩家话上屏，写事件总线 player_say）；
② 选项带 affection/flag 则直接结算；自由输入则 rule_engine.classify() 意图分类后吸收相近选项效果；
③ _agentRespond('miyuki', text)：
　LLM 可用 → assemble_prompt（人设卡 → 你的相关记忆 → 当前场景 → 知识边界 → 输出格式 → STAGE_NOTES 阶段约束）→ 智谱 GLM（thinking=disabled，25s 超时）→ 解析 JSON {say, action, expression} → guardrails.validate：合格即收（src=llm）；违规/异常重试 ≤2 次；
　仍失败 → rule_engine.respond()（意图→行为模式库，src=rules），规则命中的 affection/flag 同样结算；
④ 应答帧（带 src 标记）→ beat_idx+1 → step() 出下一拍。前端一次收到 [玩家帧, 应答帧, 下一拍] 三帧顺次播放。
谜团锁在通路 B 中是「生成后硬校验」：LLM 输出含 人类/雪女/身世/从哪/三年怎么活 等关键词且不在六种合法回应（含正典白名单）内 → 判 mystery_leak 打回。实测：「你是雪女吧？」→ LLM 一句岔开后被放行；若正面作答则必被打回并回落「我会在那里，一直等啊。一直」。

8. 运行通路 C：幕间自由行动

POST /api/act → interlude_act()：叙事压力 +6（闲逛也有代价）后分派：
· move：校验目标在 LOCATIONS[loc].adjacent 内（一次只能走邻接点）→ 换场景 → 旁白库随文；特殊地点（如祭典倒计时归零的参道）可触发条件。
· talk：Director.present_chars() 取在场者（老屋=深雪，鸟羽家=鸟羽老人，P1 亲戚会议=叔婶）→ 无人在场出氛围帧 → 有则走与通路 B 相同的 _agentRespond；鸟羽老人听过传闻时可能引用（后果回流）。
· wait：day+1、冬祭倒计时-1、压力+10 → gossip.run_daily_gossip(world) 离线传播（§11）→ day_end 事件 → 旁白 +「传闻正在悄悄流传……」提示。
每条通路末尾都经 _after_interlude()：Director 仲裁（见 §10）→ 满足则帧内附 scene_offer；P6 结束的 time_skip 旗标强制把 offer 指到 P7。

17. 并发模型与已知限制

  • 全局单例 Engine：所有会话共享一局。监督回归离线跑（0.5s）+ /api/mode 开关把冲突窗口压到最小；彻底解法是「每会话一个 Engine 实例」（已在 night_notes 立项）。
  • LLM 延迟：thinking disabled 后实测 0.7~1.0s；超时 25s ×重试 2 后必回落规则引擎，玩家永远能得到回应。
  • FastAPI 默认单进程同步端点——引擎状态无锁但串行访问天然安全；若改多 worker 必须先把状态外置（Redis/SQLite）。
  • 资产为程序化示意级；接生图/音乐模型后按 gen_*.py 同名替换即可整体升级。
