# 开发文档 C4：护栏反馈式重试 + 正典台词检索注入（few-shot）

- **总报告排名**：第 4 位 ｜ 相关性 9 · 适用性 10 · 补充价值 8.5 ｜ 总分 27.5
- **论文依据**：《论文讲解/18_SOTOPIA-π》——自然语言反馈打磨轨迹：把"哪里不合格"写进重试，比盲重试高效得多；《论文讲解/01_Generative_Agents》——few-shot 示例锚定行为；《论文讲解/14_Re3》——候选重排/局部修复优于整段重来。**直接依据**：《架构设计V1.md》第四节第 2 条「生成后校验+**带错误反馈的重试**（最多 2 次）」——设计里写了，实现没做。
- **批次**：第 1 批 ｜ **预估**：0.5 天 ｜ **依赖**：无；C1 上线后检索注入换用同一套 MemoryStream

## 一、目标（一句话）

① 护栏拦截后把**违规原因**喂回模型重试（现在是同样的 prompt 盲试 2 次）；② 把圣经 §7 正典语料库检索 2~3 条注入 prompt 作语气锚点——目前这套全项目最贵的资产只用于规则引擎兜底和白名单，**从没进过 LLM 的上下文**。

## 二、现状与差距（代码级）

```python
# engine.py::_agentRespond 现状（:517-532）
for attempt in range(2):
    ...
    prompt = assemble_prompt(...)          # 两次循环 prompt 完全相同
    out = LLM.chat(prompt, ...)
    if guardrails.is_acceptable(char_id, say, w.phase):
        return {...}
    # 违规后：无任何记录，直接进第二次一模一样的调用
```

- **盲重试**：违规原因（称谓缺失？句长？谜团泄漏？）没有传回模型；同 prompt 同温度下第二次大概率重犯——重试形同虚设；
- **无 few-shot**：`llm.py::assemble_prompt`（:102-111）拼装 persona + 记忆 + 场景 + 知识边界 + 输出格式，**没有一条正典台词示例**；圣经 §7 的 P1~P10 逐场景语料、§2.1 台词引擎硬规则全靠 system prompt 的抽象描述传达，LLM 只能"理解"风格而非"模仿"风格——这正是"AI 腔"和风格漂移的根源（架构 V1 坑 1）。

## 三、详细修改方案

### 3.1 护栏解释器（agents/guardrails.py 增补）

```python
ISSUE_EXPLAIN = {
    'missing_address': '台词未称呼对方「小修」',
    'forbidden': '使用了禁忌表达',
    'too_long_segment': '单句超过 42 字，请拆成短句',
    'missing_tone': '缺少句尾语气词（哦/呢/啦/嘛/吧/――）',
    'mystery_leak': '触及了核心谜团却未用四种合法回应之一'
                    '（睁大眼睛/沉默片刻/一如往常的微笑/「我会在那里，一直等啊。一直」）',
    'identity_declaration_early': '本阶段你还不能说出姐姐身份宣言',
    'name_leak_early': '本阶段你还不能说出自己的名字',
}

def explain(char_id, text, stage):
    return [ISSUE_EXPLAIN.get(i, i) if ':' not in i
            else ISSUE_EXPLAIN.get(i.split(':')[0], i)
            for i in validate(char_id, text, stage)]
```

### 3.2 反馈式重试（engine.py `_agentRespond` 改造）

```python
last_issues = None
for attempt in range(2):
    prompt = assemble_prompt(...)
    if STAGE_NOTES.get(w.phase):
        prompt += ...
    if last_issues:
        prompt += ('\n\n【上一次回应未通过设定校验，必须修正】\n'
                   f'上次回应：「{last_say}」\n'
                   '问题：\n- ' + '\n- '.join(last_issues) +
                   '\n请重新输出（保持一行 JSON 格式），不要重蹈以上问题。')
    out = LLM.chat(prompt, ..., temperature=0.7 if attempt == 0 else 0.4)  # 重试降温
    ...
    issues = guardrails.explain(char_id, say, w.phase)
    if not issues:
        return {...}
    last_issues, last_say = issues, say
```

规则：重试温度 0.4；第二次仍失败才回落规则引擎（回落逻辑不变）。

### 3.3 正典检索注入：新模块 `agents/canon.py`

```python
# 数据：从圣经§7/§2.1 整理 {scene: [(intent_tags, speaker, line)], ...}
CANON_CORPUS = {
    'P1': [('smalltalk', 'miyuki', '呐'), ('invite', 'miyuki', '我们去外面玩吧'), ...],
    'P5': [('ask_parents', 'miyuki', '小修，我帮你量量身高吧'), ...],
    # 与 rule_engine.INTENT_PATTERNS 的意图标签对齐
}

def retrieve_canon(scene_id, intents, char_id, k=2):
    """按场景+意图匹配，优先同角色；返回 2~3 条正典台词。"""
```

- 注入位置：`assemble_prompt()` 新增段落：

```
【你的台词示范（正典语料，模仿其语气与句式；除非玩家原话引用，不要逐字复述）】
- 「呐，你喜欢雪吗？」
- 「嘿嘿――」
```

- 离线兜底：无匹配时省略该段；
- **held-out 原则**（承接论文讲解 06 千人分身）：每场景保留 ~20% 正典台词**不进入**检索库（如 P1 的「我喜欢这雪」、P6 的「写作深和雪两个字，miyuki」）——专供 C5 评测当验证集，防止"背答案"污染评测。

### 3.4 观测

`world.emit('llm_retry', {'char', 'issues', 'recovered': bool})` → 事件日志可统计"重试救回率"（第二次成功的比例），这是护栏有效性的直接指标。

## 四、验收标准

1. 单测 `test_canon.py`：P1+意图 invite 检索出「我们去外面玩吧」；held-out 台词不出现在任何检索结果；
2. 单测 `test_guardrail_feedback.py`：`explain()` 对 6 类 issue 的文案正确；
3. 实机 A/B（各 20 次自由输入，LLM 开）：
   - 重试救回率：修改前≈0（盲重试），修改后 ≥40%；
   - `src=llm` 比例（回落规则率）下降 ≥10 个百分点（从事件日志统计）；
   - 语气词/称谓违规上屏次数为 0（本来就 0，确认不回退）；
4. `test_consistency.py` / `e2e_playthrough.py` 全绿。

## 五、风险与回滚

- **逐字复读**：few-shot 的经典副作用——prompt 里"不要逐字复述"指令 + CANON_WHITELIST 本就合法，风险低；C5 评测的"复读率"指标监控；
- **token 成本**：+2 条示例 ≈ +60 token/次调用，静态可缓存段之外的小增量；
- **回滚**：canon 注入与反馈重试各是独立 if 块，可单独关闭（建议各加 `settings.CANON_INJECT = True` 开关）。
