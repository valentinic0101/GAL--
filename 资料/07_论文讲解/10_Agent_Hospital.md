## 二、论文本身

### 2.1 要解决的问题

医疗 LLM 的困境：真实病例标注昂贵。论文构造"医院模拟器"——用模拟患者无限产出训练病例，让医生 agent 在里面**自己变强**。

### 2.2 方法

- **Evolvable Hospital**：完整模拟疾病发生→分诊→挂号→问诊→检查→诊断→治疗→随访全流程，医生、护士、患者全部由 LLM agent 扮演。
- **患者 agent 自动生成**：疾病知识库 + 基础模型批量合成病例，无需人工标注。
- **MedAgent-Zero 进化策略**："Zero" 指从零标注起步——治疗成功/失败的案例写入**病例库**，从病例中归纳出**经验库**，治疗越多医术越高。

## 三、评价所用的技术

- **外部标准基准**（不是在自设环境里自评，这点很关键）：进化后的 MedAgent-Zero（基于 GPT-3.5）在**中国医师资格考试 LPT-3 达 93.62%**、**NEJM 挑战达 91.61%**，超过 Med-PaLM 2、GPT-4 等强基线。
- **学习曲线**：展示进化收益随治疗病例数持续上升。
- **局限**：疾病演化与疗效由模拟器规则生成，与真实临床分布有差距；基准偏选择题式考试。

## 四、对 GAL 项目的启发

1. **"模拟内积累 → 外部基准验证"的闭环**：它的评测逻辑完全适用于本项目——角色 agent 在游戏内与玩家/测试脚本交互积累"对演记录"（≈病例库），定期归纳成"经验库"（≈反思产物），然后用**正典语料集**（外部金标准）验证有没有真的变好。
2. **自动患者生成 = 自动测试玩家**：Agent Hospital 用 LLM 批量造患者，本项目可以批量造**测试用玩家**（不同人格的模拟玩家 agent 自由输入），对深雪做大规模回归测试——比人工点测覆盖面大得多。
3. 领域本身（诊断流程）与 galgame 无关，不需要深入。
