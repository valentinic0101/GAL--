## 二、论文本身

### 2.1 要解决的问题

研究虚假信息、群体极化需要百万级用户的模拟，但逐个调 LLM 成本不可行。OASIS 要解决**规模与成本的工程问题**，并验证大规模 LLM agent 社会能否复现真实社会现象。

### 2.2 方法：五模块可扩展基础设施

1. **Environment Server**：关系库存 agent profile、帖子、关注关系。
2. **推荐系统**：模拟 X（Twitter）的 in-network + TwHIN-BERT 兴趣匹配 out-of-network 推荐；模拟 Reddit 的 hot score。
3. **Agent Module**：基于 CAMEL 框架；用 GPT-4o-mini 生成交互数据**蒸馏 Llama-3.1-8B 小模型**，经 vLLM 部署压成本；每个 agent 带记忆 + 21/23 种动作（关注、发帖、转发、评论等）。
4. **Time Engine**：24 维真实活跃概率分布，异步唤醒 agent（不是全员同时在线）。
5. **异步消息队列 + GPU 资源管理**（百万 agent 实验用了 24×A100）。

### 2.3 关键结果

- 复现了**信息传播、群体极化、羊群效应、回音室**等真实社会现象。
- 1M agent 谣言实验：谣言帖更多、影响更持久、自发形成回音室。
- 规模实验（196→100K）：意见多样性随规模上升；"事实纠错的羊群效应"只在 **10K+** 规模才出现——有些社会现象必须上规模才看得见。

## 三、评价所用的技术

- **现象复现验证**：用 198 条真实谣言案例对照，模拟的传播规模/最大广度 NRMSE ≈ **30%**（深度偏浅，归因于推荐系统简化）。
- **干预实验式设计**：up/down-treated 实验测羊群效应，发现 agent 的负向从众强于真人。
- **LLM-as-judge**：GPT-4o-mini 评审意见多样性与价值（注意：这引入评委偏差）。
- **消融**：去掉推荐系统则传播严重退化；TwHIN-BERT 优于 MiniLM/BERT；时间活跃特征必要。

## 四、对 GAL 项目的启发

1. **蒸馏是规模化的唯一解**：它证明"贵模型造数据 → 蒸馏小模型跑量"可行。本项目亲戚群像（5–8 人）虽不需要蒸馏，但**旁白/导演等高频低难度调用**可以用同样思路换成小模型。
2. **时间引擎**：agent 按"活跃概率"异步行动而非全员同步——本项目的每日八卦模拟可以借鉴：给每个角色一个"今晚串门的概率"，而不是所有人每晚都动。
3. **警惕 LLM-as-judge 的系统性偏差**：后续 SOTOPIA-π 实测 LLM 评委高估社交 agent 能力——本项目做自动评测时，"LLM 打分"只能作参考，正典语料硬指标才是金标准。
4. **规模-现象门槛**：有趣的涌现需要规模；galgame 只有 5–8 个活跃节点，所以**不要指望纯涌现**，必须靠导演层——这反过来印证了架构 V1 的判断。
