# 开发文档 C8：传闻强度衰减与回流强化（传播引擎 1.5）

- **总报告排名**：第 8 位 ｜ 相关性 7 · 适用性 8 · 补充价值 7 ｜ 总分 22
- **论文依据**：《论文讲解/02_S³》——消息影响 = f(时间衰减, 内容相关性, 信源真实性)，情绪传播 zero-shot 可达 r=0.73 的关键是给每条传播内容**动态权重**而非等权；《论文讲解/19_LARP》——记忆曲解/有损转码是角色记忆的**特性**而非缺陷；《论文讲解/21_A-Mem》——记忆网络随交互持续重组（新信息回写旧条目）。
- **批次**：第 4 批 ｜ **预估**：1 天 ｜ **依赖**：建议在 C1 之后（回流走记忆检索更自然）；独立可做

## 一、目标（一句话）

给每条传闻加**强度与衰减**，让八卦有"热度"：新传闻沸扬、旧传闻沉寂；NPC 按"热度 × 性格"主动引用传闻——"传播的乐趣在于后果回流到玩家"（架构 V1 §2.2）从偶然变成机制。

## 二、现状与差距（代码级）

- `gossip.py`：传播概率固定（`PERSONALITY_FILTERS[*]['p']`）、`hops>=3` 停传、扭曲模板**固定 6 条**（push_away 3 + exaggerate 3）——同一传闻传三天，文案与热度完全相同；
- **无强度概念**：`Knowledge(key, content, source, hops, distorted)` 没有时间维度；一个月后的传闻与今天的传闻在系统里无差别；
- **回流未接通**：`rumor_hooks()`（gossip.py:76-83）定义了却**没有任何调用点**；NPC 会不会引用传闻完全取决于知识库切片碰巧包含它（C1 上线前）；`wait` 的提示只有一句固定的"（镇子上，传闻正在悄悄流传……）"。

## 三、详细修改方案

### 3.1 强度字段（world.py `Knowledge` 扩展）

```python
class Knowledge:
    def __init__(self, ..., strength=1.0):
        self.strength = strength   # 0~2；1=常规，>1.3 沸扬，<0.3 沉寂

    def decay(self):               # world 每日 tick（engine.interlude_act 'wait' 分支调用）
        self.strength = max(0.0, self.strength * 0.9)
```

- 写入：新目击 `strength=1.2`（亲历更有热度）；新传闻 `strength=1.0`；
- 强化：NPC 台词引用一次 +0.1（封顶 2.0）；玩家主动问起 +0.2；
- 停传：`run_daily_gossip` 中 `kn.strength < 0.2` 等效 `hops>=3` 的跳过条件（S³ 的 temporal 因子）。

### 3.2 LLM 扭曲（可选档，gossip.py 扩展）

```python
def distort_with_llm(content, style):
    prompt = ('把下面这句话改写成「%s」口吻的转述（一句话，可以适度走样、'
              '添油加醋或拐弯抹角，但不得说出新的事实）：\n「%s」' % (style, content))
    return LLM.chat(..., max_tokens=60)   # 失败回落 rnd.choice(DISTORTIONS[...])
```

`run_daily_gossip(w, use_llm=False)`：离线/限流时维持现有模板；LLM 开时扭曲产物更活（同一条"女孩出入老屋"经叔父变"遗产怕是要出问题"、经婶婶变"老屋半夜有灯"）——每次产出缓存进模板池，逐步摆脱固定 6 条。

### 3.3 回流机制（engine.py `_agentRespond` 尾部）

```python
hooks = gossip.rumor_hooks(char_id, w)               # ← 现有函数首次接线
hot = [(c, k) for c, k in hooks if k.strength >= 0.5]
if hot and random.random() < (0.35 if char_id == 'toba' else 0.5):
    prompt_assemble 时追加：
    【镇上最近流传（你听说的，未必是真）】
    - 「听说――老屋那边，怕是有点不干净。」
```

并要求输出 JSON 增加可选字段 `"heard"`：模型若引用了传闻，置 true → 引用的那条 `strength += 0.1` 并 `world.emit('rumor_referenced', ...)`。前端世界状态面板（README"含镇上传闻"）按强度显示：`<0.3 沉寂 / 0.3~1.3 微澜 / >1.3 沸扬`。

### 3.4 产物可见性

`wait` 的 note 升级：`rumor_note` 从固定一句改为按当日新传闻的 content 摘要（"镇上有人说起『老屋半夜的灯』……"），玩家在时间推进时直接感知八卦在动。

## 四、验收标准

1. 单测 `test_gossip2.py`：
   - 强度衰减曲线：1.0 → 0.9 → 0.81 …；`<0.2` 停传；
   - 引用强化：`+0.1` 封顶 2.0；
   - `use_llm=False` 全路径回归（现有 gossip 测试语义不变）；
2. 实机（离线）：P2 后 `wait`×3，断言：toba 知识库出现 distorted 传闻且强度 >0.5；再与 toba 交谈 5 次，≥1 次台词引用传闻内容（离线规则池加一条"听说――"句式保证可测）；
3. `test_branching.py` / `e2e` / `test_consistency` 全绿（传播只影响旁支体验，不进主线路由）。

## 五、风险与回滚

- **LLM 扭曲越界**（说出新事实=泄谜）：prompt 已限"不得说出新的事实"，且产物仍走 C3 的 `check_miyuki`（若角色为深雪）与通用长度校验；异常即回落模板；
- **传闻污染主线**：回流只影响 prompt 附加段与台词，不写 flags/轴值——与分支系统隔离；
- **回滚**：`strength` 字段对旧存档兼容（缺省 1.0）；`use_llm` 默认 False，`rumor_hooks` 接线是独立 if 块。
