## 二、剧本与架构现状梳理

### 2.1 剧本结构（games 剧本 = `server/scenes/script.py`，616 行）

```
主干（正典改编，线性）：P1 初遇 → P2 清雪 → P3 姐姐宣言+雪仗 → P4 冬祭 → P5 刻身高
                        → P6 送站拉勾 → P7 三年后重逢 → P8 同居日常 → P9 再量身高 → P10 齐刘海离别
分支层（三轴·四结局）：P10 → P11 一年后的岔路（D0）
    ├─ 入山（执念≥35）→ P12M 雪径 → P0 白之彼方 ═══ END_SNOW
    ├─ 归省（默认）　 → P12B 幸福之问（D1，原文未答之问由玩家回答）
    │        ├─ 留下（bond≥50）═══ END_STAY
    │        ├─ 春天再见（bond≥50 ∧ 执念<35）═══ END_SPRING（真结局，接通 accepted_sister）
    │        └─ 兜底 ═══ END_FAR
    └─ 留京（现世≥35）→ E_TOKYO 东来的雪 ═══ END_FAR
```

- 三轴（bond/obsession/worldly）：正典选项携带增量 + 自由输入由 `agents/score.py` 打分（LLM 严格 JSON，离线关键词兜底），打分后插一句修二内心独白反馈。
- 门控哲学：**选项全部可见、点击时判定**，不足者以 `fail_text` 剧情化拒绝并回落——无死路（`tests/test_branching.py` 穷举验证）。
- 谜团锁：圣经 §1.3 四问 + 四种合法回应，实现为 STAGE_NOTES（软）+ guardrails 关键词（硬，但见 C3 缺口）。

**打分理由摘要**（详见各开发文档开头"论文依据"节）：

- **C3（29）**：谜团锁是本作红线，而当前 P1 就能让 LLM 说"我是你的姐姐"过护栏——漏洞真实存在且是 QA 已实锤的遗留项；改动只在 `guardrails.py` 一个文件内，零架构风险。相关性满分、适用性满分。
- **C1（28.5）**：`_agentRespond` 现在的"记忆"是知识库按插入顺序切片——知识库只记八卦/目击，**角色的全部经历（对话、事件）根本没有被记住**。这是全项目最大的"论文-实现"落差（Smallville 的立身之本），也是 C2/C5/C7 的地基。
- **C6（28）**：谜团锁目前只有"被动输出校验"，从没被主动攻击过；SOTOPIA 的 SEC 维度 + 互动戏剧的对抗玩家提供了完整方法论，且能自动化进回归。
- **C4（27.5）**：圣经 §7 的正典语料库是全项目最贵的资产，目前只用于规则引擎兜底和白名单——没有进 LLM prompt（架构 V1 明确要求"检索正典台词做示范"）；重试不带反馈也使护栏的二次机会形同虚设。
- **C5（27）**：现有 32 项测试全是"单句级正则断言"，回答不了"深雪立没立住"这个终极问题；Smallville 采访法 + 千人分身归一法可以直接移植。
- **C2（26）**：reflection 是 Smallville 三件套之一，也是"亲戚信念沉淀"（架构 V1 坑 3）的机制基础；依赖 C1，故排后。
- **C7（25.5）**：SENNA 用用户实验证明了 diegetic 引导优于硬推——现有 `_interlude_hint` 的固定文案正是"温和的 hard denial"；有真实收益但涉及导演层行为变化，需要小心回归。
- **C8（22）**：传播引擎骨架已在，缺的是强度衰减与主动回流；收益真实但体感增量小于前七项。
