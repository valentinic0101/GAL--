# 开发文档 C1：记忆流与三因子检索系统（Memory Stream）

- **总报告排名**：第 2 位 ｜ 相关性 10 · 适用性 9 · 补充价值 10 ｜ 总分 28.5
- **论文依据**：《论文讲解/01_Generative_Agents》——memory stream + 检索三因子（recency 指数衰减 0.995/游戏小时 × importance LLM 1~10 分 × relevance embedding 余弦）；《论文讲解/20_MemGPT》——工作记忆/回忆库/档案库分层 + memory pressure 递归摘要；《论文讲解/21_A-Mem》——记忆可链接、可演化（为 C2 反思预留接口）。
- **批次**：第 2 批 ｜ **预估**：1.5 天 ｜ **依赖**：无（C4/C2/C5 依赖它）

## 一、目标（一句话）

给每个角色建一条**记忆流**：经历（对话、事件、传闻）全部写入，检索时按"近因 × 重要 × 相关"打分取 top-k——替换掉现在 `engine.py:519-520` 那两行"按插入顺序切片"的伪检索。

## 二、现状与差距（代码级）

```python
# engine.py::_agentRespond 现状
memories = [v.content for v in w.knowledge[char_id].values()][-6:]   # ← 知识库切片
kb = [v.content for v in w.knowledge[char_id].values()][:8]
```

- `world.knowledge` 只存**知识条目**（目击/八卦：`girl_took_shuuji`、`miyuki_claims_sister` 等，共 5 个 `_witness` 写入点 + gossip 产物）——**角色的对话经历、场景事件完全没有被记下来**。P7 重逢时深雪"记得"的只有那 3 条知识，不记得 P1 的「我喜欢这雪」、P3 的雪仗、P5 的刻身高约定；
- 切片顺序 = dict 插入顺序：`[-6:]` 取"最新的知识"、`[:8]` 取"最早的知识"——既无相关性（玩家聊父母时检索不出父母相关记忆）也无重要性（"吃早餐"和"刻身高之约"同权）；
- 知识边界（kb）与记忆（memories）混用同一数据源，违反圣经 §2.2"知识边界防串戏"的设计初衷（知识边界应该窄而精确，记忆应该全而可检索）。

## 三、详细修改方案

### 3.1 新模块 `server/agents/memory.py`

```python
class MemoryEntry:
    def __init__(self, content, kind='episode', day=1, importance=3,
                 source='experience', keywords=None):
        self.content = content        # 一句自然语言（如「他红着眼睛说『……我喜欢这雪』」）
        self.kind = kind              # episode 经历 / rumor 传闻 / insight 洞察(见C2)
        self.day = day                # 写入时的 world.day
        self.importance = importance  # 1~10
        self.source = source          # experience / gossip / reflection
        self.keywords = keywords or []  # 检索关键词（写入时抽取）

class MemoryStream:
    RETRIEVE_K = 6
    W_RECENCY, W_IMPORTANCE, W_RELEVANCE = 1.0, 1.0, 1.5   # 相关性权重最高
    DECAY_PER_DAY = 0.15        # 等效 Smallville 0.995/小时，按本作 1 场景≈1 天的时间密度标定

    def add(self, entry): ...
    def retrieve(self, query, now_day, k=RETRIEVE_K):
        scored = []
        for m in self.entries:
            rec = math.exp(-self.DECAY_PER_DAY * (now_day - m.day))          # (0,1]
            rel = keyword_overlap(query, m)                                  # Jaccard 0~1
            score = self.W_RECENCY*rec + self.W_IMPORTANCE*(m.importance/10) \
                    + self.W_RELEVANCE*rel
            scored.append((score, m))
        scored.sort(key=lambda x: -x[0])
        return [m for _, m in scored[:k]]
```

**importance 打分（写入时，一次成本）**：
- LLM 可用：单条 prompt（复用 `llm.py`），输出 1~10，温控 0.1，max_tokens 8——失败回落规则；
- 规则兜底（确定性，供测试）：命中关键词表直接给档——`父母/遇难/约定/身高/名字/拉勾/喜欢` → 8；`骗子/雪仗/清雪/欢迎回家/幸福` → 6；其余 → 2；
- **keywords 抽取**：复用 `score.py` 的三个词表（OBSESSION/BOND/WORLDLY）+ 新增 `MEMORY_TOPIC_WORDS`（名字、身世、樱树、钟、柱、雪人），取命中词，无命中取 `content` 前 8 字。

### 3.2 写入时机（4 个钩子，全部在 engine.py 现有代码行内加一行调用）

| 钩子 | 位置 | 写入内容 | importance |
|---|---|---|---|
| 场景台词 | `engine.step()` 的 `line` 分支（约 :197-200） | 对**在场每个非说话角色**写：「{说话人}说：{say}」；说话者自己写「我说：{say}」 | 规则打分 |
| 玩家输入 | `submit_input()`（:436, :461 附近 `w.emit('player_say')` 处） | 对在场角色写：「修二说：{text}」 | 规则打分 |
| Agent 应答 | `_agentRespond()` 返回前（:530/:534） | 应答者写自己的话（自传式记忆） | 规则打分 |
| 八卦/目击 | `world.know()` 内部（world.py:126-129） | 同时向该角色记忆流写一条 `kind=rumor/episode` 镜像 | knowledge.hops≥1 → 4；目击 → 6 |

**去重**：同一 scene beat 只写一次（`step()` 内 line 分支天然只走一次）；同文本 24h 内跳过。

### 3.3 检索替换（engine.py `_agentRespond`）

```python
mems = self.world.memory.retrieve_for(char_id, query=text, now_day=w.day, k=6)
memories = [m.content for m in mems]                       # ← 替换原切片

```

`assemble_prompt` 的提示语从「你的相关记忆」不变（llm.py:106）；【你的知识边界】段保持，语义自此清晰：**记忆=经历过的（可带主观），知识=听说/目击的事实（用于防串戏）**。

### 3.4 持久化（world.py）

`World.__init__` 增加 `self.memory = {c: MemoryStream() for c in CHARACTERS}`；
`to_dict()` 增加 `'memory': {c: ms.to_dict() for ...}`（entries 列表直存）；`load()` 兼容：缺 key 时初始化为空（旧存档可玩）。

### 3.5 摘要与容量（MemGPT 式 memory pressure，轻量版）

每角色 entries 上限 **200** 条；达到后触发一次压缩：最旧的 50 条按天合并为 1~3 条 `kind=episode` 的摘要（离线模板拼接即可，不必 LLM），原条目丢弃——保证 100 小时游玩不膨胀。P6→P7 的三年跳跃天然由 day 差触发 recency 重置，重逢后 P1~P6 记忆靠 importance 与相关性存活——这正是三因子的设计意图。

## 五、风险与回滚

- **prompt 变长**：6 条记忆 ≈ +150 token；人设卡是静态前缀可缓存，动态段增量可接受（参考 README 成本模型）；
- **检索质量**：无 embedding 服务时 Jaccard 是弱相关性——先上关键词版（对 269 行的剧本语料足够），预留 `MemoryStream._relevance` 方法签名，未来接 embedding API 只换实现；
- **回滚**：新增模块独立，engine 钩子各一行，`retrieve_for` 降级函数返回知识库切片即恢复旧行为。
