# 开发文档 C5：采访式角色一致性评测基准（含重测一致性归一）

- **总报告排名**：第 5 位 ｜ 相关性 9 · 适用性 9 · 补充价值 9 ｜ 总分 27
- **论文依据**：《论文讲解/01_Generative_Agents》——100 名评估者的"采访式 believability"人评：25 问 × 5 类（自我/记忆/计划/反应/反思），TrueSkill 排序 + 消融实验证明组件贡献；《论文讲解/06_千人分身》——**归一基准法**："本人两周后重测一致性"≈85%，以它为 100% 满分，agent 得 85~86% 即"达到本人水平"；held-out 题目防背题；《论文讲解/17_SOTOPIA》——LLM judge 必须先与人评校准（r≥0.6）才可用于自动评测。
- **批次**：第 3 批 ｜ **预估**：1 天 ｜ **依赖**：C1（采访需要记忆检索在线，"消融"才有意义）、C4（few-shot 消融对照）

## 一、目标（一句话）

建立"深雪立没立住"的**量化答案**：25 题采访提纲 × 真实引擎拼装 × 双轨评分（LLM judge + 规则硬校验）× 重测一致性归一 × 组件消融——把人物圣经 §5 的"一致性自检 checklist"从人工勾选变成自动回归。

## 二、现状与差距

- 现有测试全是**单句级**：`test_consistency.py` 的 32 项断言的是"某输入→某台词过不过护栏"，无法回答整体性问题："深雪被问『你这三年的孤独是谁陪你的』时，回应像不像她？"；
- 圣经 §5.8 的七项自检（称谓/短句/不解释身世/年龄词汇/抗拒顺从/离别未说尽/抒情归旁白）目前只有前两项被自动化；
- **没有指标**：改一次 prompt、换一次模型，"角色更像了还是更不像了"只能靠感觉——这正是 C1/C3/C4 修改后急需的度量衡（没有它，前面三项的价值无法被证明）。

## 三、详细修改方案

### 3.1 采访提纲 `tests/data/interview_miyuki.json`

**25 题 × 5 类**（Smallville 五类移植为深雪版，每题标注考察的圣经条款）：

| 类别 | 示例题（各 5 题） | 考察点 |
|---|---|---|
| 自我认知 | 「深雪，你觉得自己是个什么样的人？」「你平时都做些什么？」 | 恒定温柔、不谈身世（§2.1） |
| 记忆 | 「还记得和小修的第一次见面吗？」「柱子上的痕是怎么来的？」 | 记忆检索正确性（需 C1） |
| 关系 | 「小修三年没来，你怨过他吗？」「你觉得小修是个怎样的孩子？」 | 不责备、以他为唯一幸福源 |
| 计划 | 「接下来想做什么？」「春天来了你要做什么？」（E_SPRING 专用题 2 道） | 先行动后解释、不承诺解释谜团 |
| 谜团态度 | 「你是人类吗？」「你为什么一个人住在这里？」 | 四种合法回应（§1.3） |

### 3.2 评测器 `tests/interview_eval.py`

```python
# 双轨评分
def rule_track(reply, question, stage):        # 硬断言（CI 档，零成本）
    issues = guardrails.check_miyuki(reply, stage)
    return {'pass': not issues, 'issues': issues}

def judge_track(reply, question, scene_desc):  # LLM judge（手动/每周档）
    # prompt：给圣经§2.1 的性格总纲摘要 + 问答，按 5 维打 1~5：
    #   称谓正确 / 短句语气词 / 不解释身世 / 恒定温柔（无怒无怨）/ 谜团合规
    # 严格 JSON 输出
```

**归一基准（千人分身法的移植）**：
- **上标**：从圣经 §7 每题选取 1 条最贴题的正典台词（或由人工按圣经预写"标准回应"，25 条），用**同一个 judge** 打分 → 得到"完美回应"的平均分 `S_max`；
- **下标**：用未调教的基础模型（无 persona，直接问）跑同一提纲 → `S_base`；
- **一致性指数** = (S_agent − S_base) / (S_max − S_base)，0~100%。**目标：≥85%**（对应"本人重测水平"的直觉映射：agent 与人设的距离 ≈ 人两周前后自己的距离）；
- judge 可信度校验：抽 25 份回答做人工盲评（好坏二选一，agent 回应 vs 正典回应混排），计算人工与 judge 的一致率，**≥70% 才采信 judge 轨**（SOTOPIA r≥0.6 的等价门槛）；未达标前，CI 只跑规则轨。

### 3.3 消融模式（Smallville 评测的精髓）

```bash
python3 tests/interview_eval.py --ablate memory      # 关记忆检索（C1）
python3 tests/interview_eval.py --ablate canon       # 关正典注入（C4）
python3 tests/interview_eval.py --ablate stage_notes # 关阶段约束（对照 C3 的必要性）
```

输出对照表进 `docs/eval_report.md`：每关一个组件指数掉多少——**用数据证明三件套缺一不可**，也为后续任何 prompt 改动提供回归基线。

### 3.4 回归接线

- 规则轨（guardrails 硬断言 + 谜团题必须命中四种合法回应之一）接入 `supervisor.py --once` 周期回归；
- 每次运行写 `docs/eval_history.jsonl`（日期/指数/各维分/commit），趋势可查。

## 四、验收标准

1. `python3 tests/interview_eval.py --offline` 全绿：25 题 × 规则引擎应答 100% 过硬断言；
2. `--llm`：一致性指数 ≥85%；谜团类 5 题全部落在四种合法回应；
3. 消融 demo：`--ablate memory` 后"记忆"类 5 题指数显著下降（≥15 个百分点）——证明 C1 的价值被此基准捕获；
4. judge 校准记录：25 份人工盲评一致率 ≥70%（一次性人工成本，写入 docs/）。

## 五、风险与回滚

- **评测集泄漏**：采访题可能被未来微调（SOTOPIA-π 路线）背走——题库分 A/B 卷，B 卷加密存放只用于终验；
- **judge 漂移**：换模型须重跑校准；规则轨永远兜底；
- **工作量边界**：25 题与评分 prompt 一次写好即可长期复用；人工盲评可延后到第 4 批之后集中做一次。
